# Lesson guidance

Exact tasks and cases are in TASKS.md. The four blocks can be used in separate sessions; completing all 24 in one sitting is not required. Each task is an independent short program with its own main. Typically 1–6 lines need completion or correction; do not require rewriting the entire scaffold. Times are estimates, never automatic completion criteria.

07: member access → copying → pointers → arrays → scope → unions. Read only the active union member; do not require fixed sizeof results.

08: getter → private-access error → reservation → const → two instances → object array. Rejection preserves state. In G08_03 the second request uses the stock remaining after the first.

09: two constructors → clamping → array construction → initializer list → removing the last item → supplied virtual example. Source review is mandatory for G09_04. G09_05 changes logical size rather than array capacity. Do not expand inheritance into new hierarchy design or dynamic memory.

10: saving → appending → negative counting → EOF bug → line validation → temporary-list loading. Explain that opening, writing and closing can fail separately. G10_03 is simple counting with a deliberately restricted input contract: its EOF check is not a general strict parser. eofbit alone does not make extraction fail; fail/bad indicates no new usable value. G10_05 receives a supplied whole-token validation helper. In G10_06 an empty file is valid but a blank line is invalid; replace old state only after complete success.

Point to concrete lines in the existing code when helping. Use only the prescribed 1–2 questions per task, after code verification. There is no separate scoring or exit quiz; feedback covers code and conceptual understanding.
